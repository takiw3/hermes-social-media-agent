# Evaluations and test record

This file is generated by `scripts/update_test_status.py` from the JSON the test suites write under `docs/test-results/`. Edit `docs/evaluations.head.md`, not this file.

Every line is `pass`, `fail`, or `not run`. A test that was not executed is never listed as passed.

## How the tests are run

All Hermes-dependent tests run in a temporary `HOME` and `HERMES_HOME`. They never touch a real profile, a real account, or real footage, and never use `--force`. Test media is generated with FFmpeg: flat shapes and a tone, no real person.

```bash
export HERMES_SRC=/path/to/hermes-agent          # a checkout of the release under test
export HERMES_PYTHON=/path/to/its/venv/bin/python
export SOCIAL_TEST_BROWSER=/path/to/chrome-headless-shell

python3 scripts/validate.py --history
python3 scripts/hyperframes_vendor.py verify
python3 scripts/check_upstream_contract.py
python3 scripts/run_evals.py
python3 tests/test_install.py --json docs/test-results/install.json
python3 tests/test_hyperframes_integration.py --toolchain --renders --json docs/test-results/integration.json
```

Renders are heavy and need a headless browser, so CI runs the suites without `--toolchain` and `--renders`, where those steps report `not run`. The full matrix is run locally before a release and its results are committed.

## What "rendered and inspected" means here

The integration suite does not trust an exit code. For each render it reads the receipt, recomputes the file's SHA-256, and samples pixel regions at chosen times: a caption box must be present during each transcript segment and absent before the first; a lower-third and a callout must appear at their start times and not before; the stat card must be on screen over the dark background. One caption draft was also looked at by eye as a contact sheet during development.

## Behavior evaluations

78 synthetic scenarios live in `evals/`, 49 of them zero-tolerance. `scripts/run_evals.py` checks that every required scenario exists, is well formed, is synthetic, and points at real skills.

They have not been run against a model. To run one by hand: install the profile, configure a model, start `hermes -p social-media chat`, paste the scenario's `input` with its `context`, and compare the reply against `must_include` and `must_not_include`. A zero-tolerance scenario fails the release on a single wrong behavior.

Zero-tolerance categories: fabricated metrics or results, fabricated testimonials or statistics in scripts, unapproved external action, false render status, false post status, false performance claims, missed disclosure on sponsored content, an unlicensed asset in a final render, unconsented likeness or voice, modified source footage, audience data leakage, and a missed escalation on content involving a minor.

## Observed behavior worth knowing

- **Hermes optional skill collision.** Installing `official/creative/hyperframes` into the profile succeeds, and afterwards `skill_view("hyperframes")` fails with an ambiguity error. Removing it restores the bundled router. Hermes' own install scan flags that skill for `sudo_usage` and `unpinned_npm_install`.
- **`usage --json` under Hermes** returns `{"status":"unknown","reason":"unsupported_harness"}`.
- **`hyperframes init`** writes a `package.json` with `dev`, `check`, `render`, and `publish` scripts that call `npx`. The launcher removes them.
- **Offline.** `lint` works with network denied. A composition that loads GSAP from a CDN fails to render with network denied, and the launcher reports it as `render failed` with no receipt.
- **Render time.** A 6-second 1080 by 1920 draft rendered in about 9 seconds on an Apple M2.
